# MedAssist

MedAssist is a healthcare clinical decision support system built for the Prompt Opinion **Agents Assemble** challenge. It combines:

- An **MCP server** with eight clinical tools — six rule-based, one LLM-powered, one orchestration tool — every clinical claim cited back to its source FHIR resource so a clinician can audit the chain.
- An **A2A agent** (Google ADK) that routes clinician requests across four specialist sub-agents and propagates SHARP context end-to-end.
- A **clinical workbench** dashboard at `/app` with editorial-clinical typography, single-surface flow, and one-click demo scenarios against verified Synthea patients.

## What's verified (as of 2026-04-27)

- MCP server compiles clean with TypeScript strict; **209 Vitest tests** passing across 13 suites.
- Agent test suite (`pytest`) passes 69 tests; ADK packaging clean under Python 3.12.
- MCP `initialize` advertises the canonical `ai.promptopinion/fhir-context` extension with the SMART scopes the eight tools need.
- A2A agent card is A2A v1 schema (`supportedInterfaces[]`, typed `securitySchemes`, `capabilities.extensions`).
- SHARP context flows end-to-end via canonical headers (`X-Patient-ID`, `X-FHIR-Server-URL`, `X-FHIR-Access-Token`) — the wire format the platform actually uses.
- Three Synthea-generated patients on the public HAPI sandbox have been exercised through every tool and frozen in [docs/test-scenarios.md](docs/test-scenarios.md).
- A deterministic quality benchmark in [docs/eval-results.md](docs/eval-results.md) reports per-tool latency, citation density, and section presence — regenerated by `npm run eval`.
- LLM-powered differential diagnosis tested live against the polypharmacy hero with NOWBIND/`gpt-4o`; the model produced a clinically coherent ranked DDx (CHF, CKD, nephrotic syndrome, cirrhosis, hypothyroidism) with each candidate citing the actual `Condition/...` resources from her record.

What's left is external: deploy, register in the marketplace, record demo, submit on Devpost. See [docs/project-status.md](docs/project-status.md).

## Architecture

```
Prompt Opinion / EHR launch
        |
        | A2A message metadata: { fhirUrl, fhirToken, patientId }
        | (extension URI: https://app.promptopinion.ai/schemas/a2a/v1/fhir-context)
        v
  MedAssist A2A Agent  (Google ADK + to_a2a, port 8001)
   ├─ before_model_callback extracts metadata into ADK session state
   ├─ Sub-agents: patient_review, medication_safety, risk_assessment, preventive_care
   └─ McpToolset.header_provider injects canonical SHARP headers per call
        |
        | HTTP /mcp with X-Patient-ID, X-FHIR-Server-URL, X-FHIR-Access-Token
        v
  MedAssist MCP Server  (TypeScript + StreamableHTTP, port 3001)
   ├─ Express middleware reads canonical SHARP headers (case-insensitive)
   ├─ Eight tools (see below)
   ├─ Dashboard served at /app
   └─ Status aggregator at /api/system-status
        |
        | FHIR R4 queries
        v
    FHIR R4 server  (default: hapi.fhir.org/baseR4)
        + optional RxNorm, OpenFDA
        + optional NOWBIND/Azure or OpenAI for differential_diagnosis
```

## Tools

The MCP server exposes eight clinical tools:

| Tool | Type | Purpose |
|------|------|---------|
| `patient_summary` | rule-based | Demographics, conditions, medications, allergies, recent labs, vitals, immunizations — all sections cited back to FHIR resource ids |
| `interpret_lab_results` | rule-based | Age/sex-adjusted reference range flagging, trends across observations, derived values (eGFR, anion gap), critical-value escalation |
| `check_drug_interactions` | rule-based | Built-in matrix + RxNorm + OpenFDA + therapeutic duplications + allergy cross-reactivity |
| `calculate_risk_score` | rule-based | CHA2DS2-VASc, HEART, Wells DVT/PE, ASCVD, CKD-EPI 2021 — each calculator returns score + variables-used table + clinical recommendation + citations |
| `identify_care_gaps` | rule-based | USPSTF screenings, CDC immunizations, condition-specific monitoring per guideline |
| `match_clinical_guidelines` | rule-based | ADA, ACC/AHA, GOLD, GINA, KDIGO targets matched against patient observations |
| `differential_diagnosis` | **LLM** | Ranked differential with cited supporting / contradicting findings + recommended next steps. NOWBIND (Azure) by default; OpenAI fallback. |
| `clinical_handoff` | orchestrator | Composes patient_summary + lab interpretation + drug interactions + care gaps + auto-selected risk scores into a single shift-handoff document |

The agent orchestrates four specialist workflows that pick from these tools as needed:

1. `patient_review`
2. `medication_safety`
3. `risk_assessment`
4. `preventive_care`

## FHIR resource citations

Every clinical claim emitted by the data-heavy tools attaches the source FHIR resource id inline:

```
- Diabetes mellitus type 2 (disorder) (onset: Jan 9, 1991) `Condition/6c4769e4-beda-5b20-7354-e94fc65c1410`
```

The dashboard renders these as compact tokens (`Condition/…c65c1410`) with the full id preserved in `title=` for hover audit. The `differential_diagnosis` LLM tool sees these citations in its grounding context and re-cites them in its supporting findings — a clinician can audit every claim back to a FHIR resource id.

## Quickstart

1. Use Python 3.12 if available. The setup script prefers `python3.12`, then `python3.11`, then `python3`.
2. Copy `.env.example` to `.env` and fill in any needed values. For the LLM tool, set either `NOWBIND_AGENT_OPENAI_API_KEY` + `NOWBIND_AGENT_OPENAI_BASE_URL` (preferred) or `OPENAI_API_KEY`.
3. Run `./scripts/setup.sh`.
4. Start the stack with `./scripts/run-all.sh`.
5. Open `http://localhost:3001/app`.

Optional helpers:

- `npm test --prefix mcp-server` — 209 Vitest tests.
- `cd agent && ./venv/bin/pytest` — 69 agent tests.
- `npm run eval --prefix mcp-server` — regenerates [docs/eval-results.md](docs/eval-results.md).
- `./scripts/smoke-test.sh` — verifies MCP + agent health endpoints.

Key local endpoints:

- Dashboard: `http://localhost:3001/app`
- MCP `/mcp` transport: `http://localhost:3001/mcp`
- MCP health: `http://localhost:3001/health`
- MCP deep health: `http://localhost:3001/health?deep=1`
- System status (combined): `http://localhost:3001/api/system-status`
- Agent health: `http://localhost:8001/health`
- Agent card (A2A v1): `http://localhost:8001/.well-known/agent-card.json`

## Standards compliance

- **MCP**: server advertises the `ai.promptopinion/fhir-context` extension in its `initialize` capabilities response with required scope `patient/Patient.rs` and read-search scopes for Observation, Condition, MedicationStatement, AllergyIntolerance, Immunization, plus `offline_access`. SHARP context resolves from canonical HTTP headers first (`X-Patient-ID`, `X-FHIR-Server-URL`, `X-FHIR-Access-Token`), with the `_meta` JSON-RPC path retained as fallback for the local dashboard's REST calls.
- **A2A**: agent card uses v1 schema (`supportedInterfaces[]`, typed-key `securitySchemes`, `capabilities.stateTransitionHistory: false`, `capabilities.extensions[]`) via the `AgentCardV1` / `AgentExtensionV1` shim copied from `po-adk-python/shared/app_factory.py`. The `before_model_callback` hook extracts `metadata["https://app.promptopinion.ai/schemas/a2a/v1/fhir-context"]` from inbound A2A messages, writes `fhirUrl`/`fhirToken`/`patientId` into ADK session state, and the `McpToolset` `header_provider` callable feeds them as canonical SHARP headers on every outbound MCP call.
- **FHIR**: R4 client supports both anonymous (public HAPI sandbox) and bearer-token authenticated servers.
